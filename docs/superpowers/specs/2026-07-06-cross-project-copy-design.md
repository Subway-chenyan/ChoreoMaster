# 跨项目复制演员与队形设计

## 目标

让应用内的演员和队形剪贴板跨项目保持完整语义。框选演员粘贴后应出现在复制瞬间的位置并默认显示；复制整个队形时，应在目标项目创建源项目全部演员、道具、分组和贴图，并恢复该队形的坐标、旋转与隐藏状态。

## 现状与根因

演员剪贴板把位置保存为 `sourceFrameId -> Position`，粘贴时使用目标项目 frame ID 查找。跨项目 frame ID 不同，因此没有位置被写入，新演员虽然创建，却在目标当前队形中不可见，并由渲染回退表现为坐标归零。

队形剪贴板只保存一个 `Frame`。跨项目粘贴保留了源演员 ID，却没有把对应演员、道具、分组或贴图带到目标项目，因此队形坐标成为无实体引用。

## 剪贴板模型

### 演员快照

演员快照包含：

- 所选演员和道具的完整定义；
- 它们引用的分组定义；
- 复制瞬间求值场景中的坐标和旋转；
- 已转为自包含形式的贴图。

粘贴时为对象和分组生成新 ID，重映射 `groupId`、`boundToId` 等引用，并把坐标与旋转写入目标当前队形。演员粘贴无条件默认显示，不继承源帧的隐藏分组设置。

### 队形快照

队形快照包含：

- 源项目全部演员和道具；
- 源项目全部相关分组；
- 当前 Frame 的位置、旋转、隐藏分组和备注；
- 所有对象贴图的自包含副本。

粘贴时先创建完整对象/分组 ID 映射，再创建新对象和新 Frame。所有对象名称保持原样，不添加 `Copy` 后缀。没有位置的对象仍被创建在项目列表中，但在粘贴队形里保持隐藏；源帧隐藏分组也按新分组 ID 恢复。

## 贴图迁移

复制命令异步深拷贝贴图：

- `data:` URL 直接保留；
- `choreo-asset:`、`blob:` 或可读取 HTTP URL 通过 `fetch` 转为 data URL；
- 成功内嵌后移除源项目 `assetPath`，避免目标保存时引用错误目录；
- 无法读取的贴图给出错误提示，且不生成表面成功、实际丢图的剪贴板。

目标项目保存时沿用现有 `externalizePerformerTextures`，把 data URL 写入目标项目自己的资源目录。重新打开目标项目后贴图仍可恢复。

## ID 与冲突规则

- 每次粘贴都创建新的对象、分组和 Frame ID。
- 目标项目存在同名对象时不复用、不改名；允许出现同名但 ID 不同的对象。
- `groupId`、`boundToId`、位置 key、旋转 key 和隐藏分组 ID 必须统一重映射。
- 目标项目已有对象和队形不得被覆盖。

## 撤销与反馈

演员粘贴继续进入现有 `paste-performers` 撤销链路，并扩展为撤销新建分组。队形粘贴需要一个复合撤销载荷，一次撤销同时删除新 Frame、新演员/道具和新分组。

复制为异步操作；成功后显示已复制数量，贴图读取失败时显示明确错误。粘贴时若没有当前目标 Frame，则不执行演员粘贴并提示用户先创建或选择队形。

## 测试

- 纯函数测试：演员快照粘贴恢复坐标；队形快照完整重映射对象、分组、绑定、位置、旋转和隐藏组。
- 回归测试：跨项目 frame ID 不同仍能显示粘贴演员；队形粘贴不添加名称后缀。
- 资源测试：项目 URL 转 data URL，保存目标项目后贴图路径属于目标项目。
- 集成检查：撤销/重做、桌面回归、TypeScript 和生产构建。

## 非目标

不使用操作系统剪贴板，不支持应用重启后的剪贴板恢复，也不迁移音乐、舞台设置、时间轴标记或整个项目历史。
