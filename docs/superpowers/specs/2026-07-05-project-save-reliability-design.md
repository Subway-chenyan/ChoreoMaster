# 项目保存可靠性设计

## 背景

用户报告点击保存后演员列表会被清空，但时间轴队形仍然存在；另有首次保存因目录权限失败、重启或更换路径后恢复的情况。当前设置页保存按钮缺少明确反馈，也没有定时自动保存和上次保存时间。

## 根因与风险

当前 renderer 在保存成功后，把主进程回读并规范化后的 `performers`、`transitions`、`stageConfig` 等数据重新写回 React 状态。保存本应是持久化操作，却反向改变了编辑状态；一旦回读为空、过期或经过兼容性过滤，演员就会在 UI 中消失，而仍引用演员 ID 的队形位置继续存在。

此外，快捷键监听 effect 没有依赖最新保存回调，可能捕获过期的项目快照。按钮、快捷键和未来的定时器如果直接各自调用保存，也可能形成并发写入。主进程当前直接覆盖 `project.json`，写入中断时缺少旧文件保护。

## 方案

### Renderer 保存协调器

所有入口调用同一个保存函数。保存开始时从最新 ref 获取完整项目快照，并记录保存中的 Promise；重复触发时复用当前请求，或在当前保存完成后对最新脏状态再保存一次，避免交错写盘。

保存成功只更新持久化元数据：最后保存快照、脏状态、上次保存时间和提示。它不调用 `setPerformers`、`setFrames` 等编辑状态 setter。只有显式加载项目时才允许磁盘数据替换编辑状态。

### 保存入口

- 设置页按钮：可点击时显示“保存项目”，进行中显示“保存中…”，成功后显示“已保存”。
- `Ctrl/Cmd+S`：阻止默认行为并调用最新保存函数。即使当前无改动，也显示短暂成功反馈，让用户确认快捷键已生效。
- 自动保存：固定五分钟定时检查，只在存在当前项目且有未保存改动时保存。

快捷键与自动保存成功时展示两秒“保存成功”提示。失败提示不自动伪装成成功，且保留未保存状态供用户重试。

### 上次保存时间

renderer 使用 Unix 毫秒保存本次会话的最后成功保存时间，设置页格式化为本地时间展示。加载已有项目时可根据项目文档的 `updatedAt` 初始化；若当前接口未稳定暴露该值，则首次成功保存后开始展示，不扩展为跨会话设置存储。

### 原子文件写入

项目服务先在项目目录写入唯一临时文件，确保写入完成后再重命名替换 `project.json`。失败时清理临时文件并保留原文件。所有路径仍限制在既有项目目录内。

## 错误处理

- IPC 或文件写入失败：不修改编辑状态、不清除脏标记，显示保存失败提示。
- 当前项目不存在：保存函数返回失败，不创建隐式项目。
- 重复保存：共享或排队处理，不允许多个 `project.json` 写入同时进行。
- 页面卸载：清除五分钟定时器和两秒提示定时器。

## 测试

- 项目服务：保存完整演员数据；原子替换失败时保留旧文件；临时文件得到清理。
- Renderer 静态回归：保存成功路径不得调用演员/队形 setter；快捷键使用最新回调；存在五分钟定时器与两秒提示；设置页展示上次保存时间和保存状态。
- 集成验证：构建 Electron 主进程，运行项目服务与桌面回归测试，再执行 Vite 生产构建。

## 非目标

不加入云同步、保存历史、可配置间隔，也不在本次任务中拆分大型 `App.tsx`。
